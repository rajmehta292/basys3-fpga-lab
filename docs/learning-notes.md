# Learning Notes: Milestone 1

## What synthesis does with the generator

`stream_counter_generator` is not a software loop. Synthesis turns its
clocked `always` block into hardware: a `DATA_WIDTH`-bit register for
`out_data`, a one-bit register for `out_valid`, an adder, and control logic.
The register values change only on a rising edge of `clk`.

`out_data` is 128 bits wide, so the value can range from zero through
`2^128-1`. Adding `1'b1` is width-extended by the expression context; the
result is stored back into the 128-bit register. Wraparound from all ones to
zero is the normal modulo-`2^128` behavior.

## Source walkthrough

In `rtl/stream_counter_generator.v`:

1. `` `timescale 1ns/1ps `` gives simulators a consistent time unit and
   precision; it does not create hardware.
2. `module ... #(parameter DATA_WIDTH = 128)` makes the source reusable at a
   different width while keeping the project default at 128 bits.
3. `clk` is the synchronous event, and `rst` clears state when sampled high.
4. `out_ready` is the consumer's permission to accept the current word.
5. `out_valid` and `out_data` are registers, so they retain their values
   between clock edges.
6. The `always @(posedge clk)` block describes flip-flop behavior.
7. The reset branch sets valid low and the first data word to zero.
8. The `!out_valid` branch presents the first word after reset without also
   accepting it on that same edge.
9. The `out_ready` branch advances the counter only after the current word was
   accepted. There is intentionally no assignment in the stalled case, so
   synthesis creates a hold condition.

In `rtl/stream_sequence_checker.v`:

1. The same width parameter sizes the input, expected value, and comparison.
2. `in_ready` is tied high because this first checker never stalls.
3. `transfer_accepted` names the protocol event instead of accidentally using
   `in_valid` alone.
4. Reset clears the 64-bit word counters, expected value, and error pulse.
5. Each accepted input is compared with `expected_value`.
6. A mismatch increments `word_errors` and raises `error_pulse` for one clock.
7. Every accepted word increments `words_checked` and advances the expected
   value, including a bad word. That behavior makes the limitation of a simple
   non-resynchronizing checker explicit.

In `sim/tb_milestone1.v`, the clock is generated by `forever #5`, reset and
ready are driven on safe half-cycle boundaries, and checks occur after clock
edges or at the following falling edge. This avoids relying on a race between
testbench blocking assignments and RTL nonblocking updates.

## Reset and nonblocking assignments

The Milestone 1 reset is synchronous and active high. `rst` is sampled only at
`posedge clk`. This makes the module's state transition easy to reason about,
but it does not by itself make a raw pushbutton safe. The later top level will
synchronize and debounce external controls.

Clocked RTL uses nonblocking assignments (`<=`). All right-hand sides are
evaluated from the pre-edge state and the register updates happen together.
That is what lets the checker observe the generator's current word at the same
edge that the generator schedules its next word.

Blocking assignments (`=`) are appropriate for many combinational blocks and
testbench stimulus, but using them carelessly in sequential hardware can make
simulation order differ from the intended flip-flop behavior.

## Valid, ready, and transfer

`valid` means “the producer has a word available.” `ready` means “the consumer
can take it now.” Neither signal alone means that a word moved. A word moves on
the clock edge where both are one:

```text
transfer = valid && ready
```

The generator therefore does not increment when `ready=0`. Holding the data is
not an optimization; it is required for the receiver to be able to sample a
stable word when it eventually asserts ready.

The checker exposes `in_ready=1` because it has no buffering or internal stall
condition in this milestone. The later FIFO will make `ready` depend on space
and will propagate backpressure to the generator.

## Why the testbench is not synthesized

The testbench creates a simulated clock with `#5` delays, drives reset and
ready, and checks results with `$display`. Delays, file output, and testbench
control constructs are simulation behavior, not FPGA hardware. The RTL files
are the hardware description; the `sim/` files are the laboratory equipment
that stimulates and measures that description.

## Why passing simulation is not enough

Simulation can show that this algorithm works for the tested stimulus. It does
not prove that Vivado inferred the intended RAM, that every path is constrained,
that setup and hold timing close at 100 MHz, that a button is synchronized, or
that a physical UART pin is mapped correctly. Those are separate synthesis,
implementation, and hardware validation gates.

## FIFO fundamentals

The FIFO is a circular buffer. A write pointer identifies the next memory
location for an accepted input word, and a read pointer identifies the next
memory location that can be prefetched into the registered output. The pointers
wrap naturally because they are eight bits wide for a 256-word depth.

`memory_count` tracks words still in the array. The output register is tracked
separately, so total occupancy is `memory_count + out_valid`. This makes the
boundary conditions visible:

- empty means there is no memory word and no output word;
- full means the output register plus memory contain 256 words;
- a simultaneous output consume and input write is allowed at full;
- an empty FIFO read attempt is counted but does not fabricate data.

The read is clocked. That is why the first word can appear one cycle after a
write, and why the testbench explicitly tests registered-output latency. Vivado
must still be consulted to confirm the chosen memory style inferred as block
RAM rather than assuming it from the RTL shape.

## PRBS and BER

The PRBS generator uses the PRBS-31 polynomial `x^31 + x^28 + 1`. For every
128-bit output word it advances the LFSR 128 times, placing successive generated
bits in successive word positions. Replicating one short pattern would not
have been equivalent.

The checker starts from the same nonzero seed, reconstructs the expected 128
bits, XORs expected and received data, and population-counts the difference.
`word_errors` counts bad words; `bit_errors` counts differing bits. A word with
three flipped bits contributes one word error and three bit errors.

## UART fundamentals

The UART transmitter sends one start bit, eight data bits least-significant bit
first, and one stop bit. At 115200 baud, the transmitter holds each bit for
approximately `100000000 / 115200 = 868` system-clock cycles. The telemetry
controller waits for the transmitter's busy handshake, so UART serialization
cannot stall the FIFO or checker.

## Timing fundamentals

The XDC constrains the 100 MHz input clock to a 10 ns period. Static timing
analysis checks whether data launched by one clock edge reaches the next
register before its setup deadline and does not arrive too early for hold time.
The authoritative hardware gates are positive setup/hold slack, no
unconstrained paths, and review of critical warnings. Simulation cannot prove
any of those properties.
